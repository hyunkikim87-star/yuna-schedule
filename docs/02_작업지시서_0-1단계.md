## 1-1. 새 데이터 구조 + PIN

### 할 일
- 기획서 4장 테이블: `classes`, `class_exceptions`, `one_day_events`, `places`
- 회차 계산 함수: 기간(from~to)을 주면 정규 수업(요일·기간) + 예외(휴강·변경) + 원데이를 합쳐 **실제 날짜 기준 회차 목록**을 돌려줌
- API (새 경로, 기존 `/api/schedules`는 그대로 둠)
  - `GET /api/sessions?from=YYYY-MM-DD&to=YYYY-MM-DD` → 회차 목록 (날짜, 시간, 수업명, 장소, 준비물, 메모, 종류, 원본 id, 겹침 여부)
  - `GET/POST/PUT/DELETE /api/classes`, `/api/one-day-events`, `/api/places`
  - `POST /api/classes/{id}/exceptions` (휴강·이 날만 변경), `DELETE …/exceptions/{id}`
- PIN 잠금: 가계부 v2와 같은 방식 (해시는 환경변수 `APP_PIN_HASH`, 세션 쿠키 30일, 5회 실패 시 5분 잠금). PIN 값은 코드·로그·채팅에 남기지 않기

### 테스트 (가짜 데이터, 날짜 고정)
- 매주 토요일 수업 + 휴강 1회 → 그 날짜만 빠짐
- 이 날만 시간 변경 → 그 회차만 바뀜
- 종료일 연장 → 회차 늘어남
- 달 경계(10/31 토 ~ 11/1 일)가 한 주말로 나옴
- 같은 시간 두 수업 → 겹침 표시
- PIN 없이 API 호출 → 401

### 체크리스트
- [ ] 위 테스트 통과
- [ ] 기존 `/api/schedules` 그대로 동작

## 1-2. 화면 (React, 가계부 v2 스타일)

- 하단 탭: **홈(이번 주말) · 달력 · 수업 · 설정**
- 홈: 다음 수업 한 줄 → 토·일 카드(시간순, 빈 시간 안 그림) → 장소 누르면 네이버지도 검색 → 준비물 칩 → 겹침 배지 → ‹ › 주말 이동
- 달력: 월 달력 + 점, 날짜 누르면 바텀시트
- 수업: 정규/원데이 목록(학기별), + 버튼 바텀시트 입력, 정규 수업 상세에서 휴강·이 날만 변경·기간 연장
- 입력: 시간은 휠 또는 칩, 장소는 목록+직접 입력
- 모바일 375px 기준, 큰 글씨, 넉넉한 여백. 가계부 v2(`household-budget` 저장소 frontend)의 컴포넌트·색 체계를 참고해도 됨

### 체크리스트 (Aside가 테스트 주소에서 확인)
- [ ] PIN 틀림 안내, 5회 잠금, 새로고침 후 유지
- [ ] 홈에서 이번 주말 수업이 시간순, 준비물 보임
- [ ] 정규 수업 등록 1번 → 달력에 매주 표시
- [ ] 휴강 하루 → 그 날만 사라짐
- [ ] 원데이 수업 등록 → 그 날짜에만

## 1-3. 기존 데이터 옮기기 (테스트 DB에서만)

기획서 4장 '옮기기 규칙' 그대로. **운영 DB는 건드리지 않고**, 0단계 백업 JSON → 로컬/테스트 DB로.

1. 주차 → 실제 날짜 변환 (`day`에 날짜 문자열이 들어 있는 2건은 그 날짜 그대로)
2. 정규 수업으로 묶기 / 원데이로 남기기 → **결과 표를 먼저 보여주고 멈춰** (수업명, 요일, 시간, 장소, 기간, 휴강일, 묶인 회차 수)
3. 중복 12건 합치기 (목록은 기획서 1-3)
4. 이름 표기 통일 후보 표 → 사용자 확인 받은 것만 적용
5. 검증: 날짜별 (수업명, 시작시간) 목록을 원본과 비교 → 차이는 중복 12건과 확인받은 이름 변경뿐이어야 함

### 체크리스트

- [ ] 회차 수: 원본 217 − 중복 12 = 205 (이후 추가분 있으면 그만큼)
- [ ] 날짜별 대조 차이 0 (허용된 것 제외)
