## 1. 왜 개편하나

사용자 의견: "촌스럽고, 사용성이 썩 좋지 않다."

### 1-1. 화면 문제 (2026-10-25 직접 확인)
- 파란 헤더 바 + 브라우저 기본 드롭다운(년/월) + ◀ ▶ 버튼. 오래된 관리자 화면 느낌.
- 9시~17시 시간표를 통째로 그려서, 수업 2~3개인 주말에도 화면 대부분이 빈칸.
- 같은 시간 수업이 2개면 카드가 겹쳐서 하나처럼 보임 (중복을 알아채기 어려움).
- 수정 창의 시간 선택이 10분 단위 55개짜리 드롭다운.
- 수정 창에 날짜가 없음 (요일만 있음). 이 주만 고치는지 전체를 고치는지 알 수 없음.
- 잠금 없음. 주소만 알면 보기·수정 창 열기 가능 (저장까지 되는지는 시험 안 함).

### 1-2. 데이터 구조 문제 (근본 원인)
현재 한 줄 = `year, month, week(월 안의 주차), day(SAT/SUN), class_name, location, supplies, memo, start_time, end_time`

- **실제 날짜가 없다.** '10월 5주차 = 10/31~11/1'처럼 주가 달 경계에서 잘림.
- **반복 수업 개념이 없다.** 와이즈미술학원처럼 매주 하는 수업도 주마다 한 줄씩. 연장·시간 변경·휴강을 주마다 손으로 해야 함.
- 평일 수업(공휴일 등)은 `day`에 날짜 문자열을 넣는 식으로 우회 (`2026-07-17`, `2026-08-17`).

### 1-3. 현재 데이터 현황 (2026-10-25)
- 전체 217건, 2026-06 ~ 2027-02 (6월 31 / 7월 36 / 8월 35 / 9월 26 / 10월 19 / 11월 16 / 12월 11 / 1월 28 / 2월 15)
- 준비물 있는 수업 95건, 메모 있는 수업 55건, 시간 미정 0건
- **중복 12건** (같은 주·요일·수업명·시작시간). 개편 때 데이터 옮기면서 정리하기로 함 (사용자 결정 2026-10-25)
  - 와이즈미술학원: 9월 1·2·3주, 10월 3·4·5주, 11월 1주 (7건)
  - 바둑&체스교실: 9월 1·2·3주, 10월 2주 (4건)
  - 부엉이시계만들디: 9월 3주 일요일 (1건)
- **이름 표기가 섞임** (같은 수업으로 보임, 옮길 때 통일 후보)
  - '와이즈미술학원'(35) / '와이즈 미술학원'(8)
  - '자신감 업 신체놀이 스포츠팡팡'(11) / '자신감 웁 …'(40, 오타로 보임)
  - '동화읽고 과학놀이'(10) / '동화 읽고 과학 놀이'(1)
  - '수업'이라는 이름만 있는 기록 3건 (확인 필요)
  - '부엉이시계만들디' (오타로 보임)

## 2. 목표

1. 열자마자 **이번 주말에 뭐가 있는지, 뭘 챙겨야 하는지** 보인다.
2. 매주 하는 수업은 **한 번만 등록**한다. 연장·휴강·시간 변경은 한 곳에서.
3. 가계부 v2와 같은 **토스 스타일**(카드, 바텀시트, 큰 글씨, 넉넉한 여백).
4. **PIN 잠금.**
5. 기존 217건을 잃지 않고 옮긴다 (중복·표기 정리 포함, 원본 백업 보관).

## 3. 화면 구성 (하단 탭 3~4개)

### 3-1. 홈: 이번 주말
- 맨 위: "다음 수업 · 토 10:00 와이즈미술학원 · 2시간 뒤" 같은 한 줄
- 토·일을 날짜별로 나눠 수업 카드를 시간순으로 (빈 시간대는 그리지 않음)
- 카드: 수업명, 시간, 장소(누르면 네이버지도), 준비물 체크칩, 메모
- 수업 사이 이동 간격 표시 (예: "이동 10분", 장소가 바뀌면 강조)
- 같은 시간 겹치는 수업은 경고 배지
- 주말 넘기기: ‹ › 로 지난/다음 주말 (주는 실제 날짜 기준, 달 경계에서 안 잘림)

### 3-2. 달력
- 월 달력, 수업 있는 날 점(지점·종류별 색)
- 날짜 누르면 그날 수업 목록 바텀시트
- 평일·공휴일 수업도 그 날짜에 그대로 표시

### 3-3. 수업 관리
- **정규 수업** (반복): 수업명, 요일, 시간, 장소, 기간(시작일~종료일), 준비물, 메모, 색
  - 휴강일 추가/해제 (예: 2/6 휴일)
  - "이 날만 시간 변경" 같은 예외
  - 기간 연장 = 종료일만 바꾸면 끝
- **원데이 수업**: 날짜 하나짜리 (문화센터 일일 특강 등)
- 학기별로 묶어 보기 (가을학기 / 겨울학기)

### 3-4. 설정
- PIN 변경
- 자주 가는 장소 목록 (이마트 수지, 스타필드 위례, AK플라자 분당, 파크뷰 상가 …)
- 데이터 내보내기(백업 JSON)
- (선택) 구글 캘린더용 .ics 구독 주소

### 3-5. 입력 방식 (가계부와 같은 바텀시트)
- 시간: 드롭다운 대신 시·분 휠 또는 자주 쓰는 시간 칩(10:00, 13:00, 15:10 …)
- 장소: 목록에서 고르기 + 직접 입력
- 저장 후 홈/달력 즉시 반영

## 4. 데이터 구조 (제안)

| 테이블 | 열 |
|---|---|
| `classes` (정규 수업) | id, name, weekday(0~6), start_time, end_time, location, start_date, end_date, supplies, memo, color, term(학기명), created_at |
| `class_exceptions` (예외) | id, class_id, date, type(cancel / change), start_time, end_time, location, memo |
| `one_day_events` (원데이) | id, name, date, start_time, end_time, location, supplies, memo, color |
| `places` | id, name, map_url |

- 화면에 보이는 "회차"는 `classes` + 예외로 계산해서 만든다 (회차를 DB에 미리 다 만들어 두지 않음).
- 날짜·시간은 한국 시간(KST) 기준으로 저장.

### 기존 데이터 옮기기 규칙 (마이그레이션)
1. 원본 217건을 JSON으로 백업 → `backup/` 폴더 (이 문서 폴더 아래)
2. 주차(year·month·week·day) → 실제 날짜로 변환. 변환 결과를 표로 먼저 보여주고 확인받기
3. 같은 이름·요일·시간·장소가 매주 이어지면 정규 수업 1개로 묶음. 빠진 주는 휴강 예외로
4. 한 번만 있는 건 원데이 수업
5. 중복 12건은 하나로 합침 (준비물·메모가 다르면 합쳐서 보존)
6. 이름 표기 통일은 사용자가 확인한 것만
7. 옮긴 뒤 검증: **날짜별 회차 수와 수업명이 원본과 일치**하는지 (중복 12건 제외) 표로 대조

## 6. 진행 방식 (가계부와 동일)

- 단계마다: 계획 보여주기 → 진행 → 테스트·체크리스트 보고 → 커밋·push → 멈춤
- **pytest(또는 해당 테스트)와 빌드가 성공해야만 커밋·push** (`&&`로만 연결, `| tail` 등으로 실패 코드 가리지 않기)
- 테스트는 실제 시계에 기대지 않기 (날짜 고정)
- 지금 앱(운영)은 전환 전까지 그대로. 새 버전은 `v2` 브랜치 + Railway 새 서비스(테스트 주소)
- 전환: 백업 → 데이터 옮기기 → 원본과 대조 → 주소 전환 → 예전 서비스는 1~2주 보관 후 삭제
- 확인은 Aside가 테스트 주소에서 직접 눌러보고 보고
